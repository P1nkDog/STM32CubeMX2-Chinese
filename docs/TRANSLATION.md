# 参与翻译指南

本项目的核心资产是**词典**（`dict/localization.json`）：一组"英文字面量 -> 中文替换"的映射条目。
词典由人工翻译维护，任何改动都会通过安全校验，确保不会破坏 STM32CubeMX2 的界面。

本指南面向想参与翻译的贡献者，完整说明从"导出待翻译清单"到"提交更新"的全流程。

---

## 1. 词典与 CSV 的关系

- **词典**（`dict/localization.json`）：程序实际使用的映射，每条包含
  `id`（唯一标识）、`en`（原文）、`zh`（中文）、`expect`（原文在 bundle.js 中的出现次数，用于安全校验）。
- **CSV**（`manual-translate.csv`）：人工翻译的工作表，由程序从 bundle.js 全量扫描生成，
  覆盖 17 类常见 UI 文本模式（菜单、按钮、标题、提示、占位符、弹窗等）。

工作流：

```
导出 CSV（程序扫描 bundle.js） -> 人工填写 zh 列 -> 导入 CSV（程序重建词典） -> 汉化验证
```

---

## 2. 准备工作

1. 安装 STM32CubeMX2（建议与词典标注的已验证版本一致，见词典 `targetApp.testedVersions`）。
2. 克隆本仓库。
3. 运行程序，主菜单选 `1) 环境/安装检查`，确认能定位到安装目录且 bundle.js 存在。
   （找不到时可用 `-g <安装目录>` 参数指定。）

---

## 3. 导出翻译表

主菜单 `6) 高级 -> 2) 导出翻译表`，或命令行：

```powershell
python main.py --export-csv
```

生成的 CSV 默认在程序目录下（EXE 旁或 `%LOCALAPPDATA%\STM32CubeMX2-Chinese\`），
名为 `manual-translate.csv`。

CSV 列说明：

| 列 | 说明 |
|----|------|
| id | 条目唯一标识，由来源类型 + 序号生成，不要修改 |
| kind | 来源模式：label / title / tooltip / header / placeholder / message / content / text / ternary 等 |
| count | 原文在 bundle.js 中的出现次数 |
| en | 原文（扫描自 bundle.js） |
| zh | 中文翻译，**这是你要填的列** |
| from_dict | 1 表示该条已存在于词典中（zh 已有值），0 表示新条目 |
| skip | 填 1 表示跳过该条（不写入词典），留空表示正常导入 |
| note | 备注（可选） |
| match | 程序匹配到的完整原文片段，用于核对上下文 |

---

## 4. 填写翻译

用 Excel、WPS 或任意支持 UTF-8 的编辑器打开 CSV，只修改 **zh 列**。

### 翻译规范

1. **术语保留英文**：GPIO、DMA、NVIC、EXTI、SPI、CMSIS、Pack、MCU、FreeRTOS 等产品名/专有名词不翻译。
2. **引号数量必须一致**：`en` 和 `zh` 中英文双引号（`"`）的数量必须相同，
   否则导入会被安全校验拦截（防破坏 JS 结构）。
3. **不要修改 en、id、match 等列**，只填 zh。
4. **格式占位符**：若原文含 `{0}`、`%s` 等占位符，中文中保留相同顺序。
5. **不确定的条目留空**：空 zh 不会被导入，宁缺毋滥，避免错翻。
6. **乱码/无意义字符串可跳过**：如 `cxFwFuBDE9eRGwGJyiZ7` 这类疑似哈希/ID 的文本，
   在 skip 列填 1。

### 填写技巧

- CSV 已按原文在 bundle.js 中的出现位置排序，多次导出顺序稳定，方便增量翻译。
- 已翻译条目（from_dict=1）会预填中文，重点补 from_dict=0 的空白行。
- 不确定某条文本出现在界面的哪里时，可用原文在 CubeMX2 里搜索定位。

---

## 5. 导入翻译表

主菜单 `6) 高级 -> 3) 导入翻译表并更新词典`，或命令行：

```powershell
python main.py --import-csv
```

导入过程：

1. 程序把 zh 列的中文**还原成完整 JS 字面量**（自动处理 label、title、菜单等 20 余种结构形态）。
2. 重新统计 `expect`（原文在 bundle.js 中的实际出现次数）。
3. 通过安全闸的条目写入词典；结构错误或引号数不一致的条目被跳过并计数。

导入完成后输出统计：`新增/更新 N 条，跳过 M 条，结构错误 K 条`。

> 注意：导入会更新的是**用户词典**（程序目录下 `localization.json`），
> 不是仓库里的 `dict/localization.json`。提交时需把更新内容同步到仓库词典文件。

---

## 6. 验证

1. 完全退出 STM32CubeMX2。
2. 运行程序，主菜单 `2) 一键汉化`。
3. 启动 STM32CubeMX2，检查新翻译是否生效、界面是否正常。

汉化失败条目会以 `!!` 标记显示（found 与 expect 不一致时跳过），
可结合 `6) 高级 -> 1) 预览替换（不写盘）` 先做干跑统计。

---

## 7. 提交更新

1. 将更新后的 `dict/localization.json` 提交。
2. 如果新增了很多翻译，同步更新词典 `version` 字段（如 `0.1.0` -> `0.1.1`），
   这样用户运行"词典更新"才能检测到新版本。
3. 发起 Pull Request，CI 会自动校验词典结构（`tools/check_dict.py`），
   通过后即可合并。合并后用户即可通过"词典更新"拉取到新翻译。

---

## 8. 常见问题

**Q: 导入时报"结构错误"怎么办？**
A: 检查该行 zh 的引号数量是否与 en 一致，去掉多余/缺失的引号后重试。

**Q: 汉化后某条没生效？**
A: 可能原因：1) 词典未包含该条（重新导出 CSV 查看）；2) expect 与当前版本不匹配
（CubeMX2 升级后原文出现次数变化，程序会安全跳过，等待词典更新适配新版本）。

**Q: 某条翻译后界面变乱/功能异常？**
A: 立即执行主菜单 `3) 一键回滚`，然后修正该条翻译（多半是引号或格式占位符问题）。
